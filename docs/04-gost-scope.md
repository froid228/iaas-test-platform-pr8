# ГОСТ Р 56939—2024 и границы платформы

Официальное название: «Защита информации. Разработка безопасного программного обеспечения. Общие требования». В [карточке Росстандарта](https://protect.gost.ru/gost/details/f3818925-a96f-4f55-96e9-46b44720ee64) указаны область применения и дата введения 20.12.2024. Стандарт устанавливает требования к работам по созданию безопасного ПО и устранению недостатков, включая уязвимости.

Отсюда следует проектное ограничение: отдельная платформа испытаний может поддерживать часть работ и сбор материалов. Она не подтверждает автоматически соответствие всего процесса разработки стандарту.

## Что необходимо добавить для ВКР

1. Составить матрицу: пункт стандарта → применимость → функция → доказательный материал → критерий приёмки.
2. Различать безопасность тестируемого ПО и безопасность самой платформы.
3. Выбрать реальные сценарии для демонстрационного клиент-серверного ПО и описать ожидаемый результат каждого.
4. Сохранять версии тестов, параметры и хеши артефактов; предусмотреть права доступа и сроки хранения.
5. Выпускать протокол, позволяющий установить, что, где, когда и какими проверками испытывалось.

`testSuite` и `evidenceUri` в текущем API — начальные точки для такой связи. Строковая ссылка не означает, что файл существует, проверен или защищён от изменения. Демонстрационный сценарий не является испытанием по ГОСТ.
