# Разбор практической работы № 8

Источник: `../Практическая работа №8 Создание приложения с микросервисной архитектурой.docx` в родительском каталоге проекта. Тема задания: «Создание приложения с микросервисной архитектурой».

Разработать микросервисную систему на Spring Cloud или аналогах. Предметная область выбирается самостоятельно и должна быть уникальна в учебной группе. В этом проекте выбрана платформа подготовки инфраструктуры и управления тестированием клиент-серверного ПО. Уникальность темы нужно сверить с группой.

## Требования и принятые решения

| № | Требование методички | Решение в проекте | Что предъявить при сдаче |
| --- | --- | --- | --- |
| 1 | Авторизация по OAuth2 | Keycloak, JWT Resource Server, scopes `platform.read`/`platform.write`, audience `platform-api` | Получение токена, 401 без токена, 403 без нужного scope, успешный запрос |
| 2 | Config Server с Git как источником | `config-server`, отдельный локальный Git backend, ветка `main` | История Git и ответ `/{application}/default/main` с версией commit |
| 3 | API Gateway | Spring Cloud Gateway, маршруты `/api/**` | Все пользовательские запросы через порт 8080 |
| 4 | Service Discovery | Eureka | Зарегистрированные сервисы в реестре |
| 5 | Балансировщик | Spring Cloud LoadBalancer, маршруты `lb://`, Feign без фиксированного URL | Два экземпляра project-service и чередование заголовков |
| 6 | Минимум три предметных микросервиса | project-service, environment-service, test-run-service | Раздельные API, ответственность и приложения |
| 7 | Взаимодействие через FeignClient | test-run-service проверяет проект и шаблон стенда через Feign | Успешный запуск и отказ для отсутствующей ссылки |
| 8 | Работа с БД | Spring Data JPA, PostgreSQL, Flyway | Сохранение и чтение данных после перезапуска приложения |
| 9 | Отдельный экземпляр БД у каждого микросервиса | project-db, environment-db, test-run-db | Три разных контейнера PostgreSQL, разные тома |
| 10 | Unit-тесты | JUnit 5, Mockito, MVC security tests | Успешный `./mvnw verify`, отчёты Surefire |
| 11 | Файлы развёртывания | Dockerfile и compose.yaml подготовлены | Воспроизводимый запуск; Kubernetes-манифесты добавить следующим этапом |
| 12 | Развёртывание в Yandex/VK Cloud; при невозможности — локальный Minikube | Запланировано | Реальные работающие ресурсы, команды и скриншоты |

Подготовленная конфигурация не равна проверенному развёртыванию. Актуальная проверка описана в `verification.md`.

Теоретическая часть методички также рассматривает CQRS и Event Sourcing, но в перечне обязательных требований они не названы. Для первой итерации используются JPA и явный жизненный цикл запуска. Журнал доменных событий можно добавить после появления runner и необходимости восстанавливать историю.

## Минимальный сценарий защиты

1. Показать компоненты системы и три отдельные БД.
2. Продемонстрировать запрет анонимного доступа и получение OAuth2-токена.
3. Зарегистрировать клиент-серверное ПО и шаблон стенда.
4. Создать запуск: test-run-service проверяет обе ссылки через Feign/Eureka.
5. Повторить с отсутствующим UUID: получить 422 без сохранения запуска.
6. Показать смену состояний и сохранённую запись результата; указать, что runner пока отсутствует.
7. Показать две реплики, балансировку и обработку недоступности зависимости.
8. Показать тесты, конфигурацию из Git и фактическое развёртывание в выбранной среде.
