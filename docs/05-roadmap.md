# План продолжения

## Этап 1. Управляющее ядро — текущая итерация

- Шесть Spring-приложений, три предметные модели, три отдельные БД.
- OAuth2/JWT, API Gateway, Eureka и балансировка, Feign.
- Git Config Server, миграции схем и тесты.
- Dockerfile, Compose, демонстрационный API-клиент, заготовка отчёта.

Критерий закрытия этапа: успешная сборка и реальный сквозной сценарий на Docker-стенде. Текущую проверку см. в `verification.md`.

## Этап 2. Завершение практической № 8

1. Запустить Compose при включённом Docker Desktop.
2. Выполнить `scripts/demo.py`, показать ошибки доступа и некорректных ссылок.
3. Поднять две реплики, подтвердить балансировку по заголовкам экземпляров.
4. Остановить зависимый сервис, проверить 503, восстановить и повторить запрос.
5. Проверить сохранение данных после перезапуска контейнеров.
6. Подготовить Kubernetes-манифесты и развернуть в Yandex/VK Cloud либо локальном Minikube. Адаптировать Git backend, секреты, issuer/JWK и постоянные тома.
7. Снять настоящие скриншоты, заполнить отчёт и указать фактические ограничения прототипа.

Готовность практической определяется всеми обязательными требованиями методички. Один локальный запуск Compose её не закрывает.

## Этап 3. Настоящая выдача инфраструктуры

Выбрать демонстрационное клиент-серверное ПО и инфраструктурный провайдер. Реализовать выдачу серверной и клиентской ВМ, отдельную сеть, проверку готовности, квоты и удаление ресурсов. Сохранять идентификаторы ресурсов и восстанавливать очистку после сбоев. Проверить негативный сценарий частично созданного стенда.

Критерий: запрос через API создаёт реальный изолированный стенд, а завершение или отмена освобождает его ресурсы.

## Этап 4. Исполнение проверок

Добавить worker/runner, версионируемые наборы тестов, установку дистрибутива, тайм-ауты, отмену, повторный запуск и идемпотентность команд. Отделить права оператора от прав runner, который завершает запуск. Сохранять журналы и файлы в объектное хранилище; не исполнять произвольные пользовательские команды в управляющих сервисах.

Критерий: выбранный набор проверок действительно выполняется на выданном стенде; результат связан с конкретной сборкой и конфигурацией.

## Этап 5. Материалы по ГОСТ и эксперимент

Уточнить применимые положения по полному тексту стандарта, добавить каталог требований и дефектов, аудит переходов и формирование протоколов. Провести измерения ручного и автоматического процесса и оформить результаты ВКР.

Рекомендуемый следующий шаг: подтвердить первый сквозной запуск, затем выбрать конкретное тестируемое ПО и способ выдачи ВМ. От этого зависят образы, ОС клиентов, установка и инструменты проверок.
